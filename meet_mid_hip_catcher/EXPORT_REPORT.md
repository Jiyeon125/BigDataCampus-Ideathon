# 데이터 분석 결과 반출 신청 보고서

> **프로젝트명**: 차세대 만남 상권 후보지 선정 (meet_mid_hip_catcher)
> **작성 목적**: 서울시 빅데이터캠퍼스에서 받은 원본 데이터를 어떻게 가공해서
> 어떤 산출물을 반출하려고 하는지, 그리고 그 산출물이 왜 반출 정책상 안전한지를
> 산출물 단위로 기술한다.
>
> **분석 단위**: 모든 분석은 **행정동(행정동코드 또는 행정동명)** 단위로 집계되었으며,
> 개별 거래·개인 식별 정보는 어떠한 산출물에도 포함되지 않는다.

## 2. 전체 처리 흐름 요약

```text
[원본 데이터 4종 (캠퍼스 내부 raw)]
        │
        │  ① 인코딩/구분자 자동 탐지 (utf-8 / utf-8-sig / cp949 × , | \t)
        │  ② 컬럼명 매칭 (find_col: 정확일치→부분일치)
        │  ③ 날짜를 YYYY-MM 으로 통일
        ▼
[행정동 × 월 단위 내부 집계]  →  outputs/internal_only/DO_NOT_EXPORT_*.csv  (반출 금지)
        │
        │  ④ 최근/이전 기간 비교(증가율), 비율, 카운트→z-score
        ▼
[행정동별 1차 점수 4종 (z-score 가중합)]
   소비성장점수 · 2030유입점수 · 로컬성점수 · 접근성점수
        │
        │  ⑤ 0~1 minmax 정규화 후 도메인 가중합
        ▼
[최종 만남 상권 후보 점수 + 후보유형]
        │
        ▼
[발표·반출용 CSV/PNG] → outputs/export_safe/
   (save_export_safe 함수가 50여개 금지 컬럼명 검사 후 통과한 것만 저장)
```

- 원본 행 출력 금지: `df.head() / print(df) / display(df)` 류 호출이 코드에 없음.
- 카드이용금액계·이용건수계·popl_cnt·업소수·정류장수·역수 등 원값은 export_safe 컬럼 차단 리스트(`BANNED_EXPORT_COLUMNS` 약 50개)에 등록되어 있고, `save_export_safe()` 가 위반 시 `RuntimeError` 를 발생시켜 저장이 차단된다.

| 항목 | 내용 |
|------|------|

| **사용 컬럼** | 기준일자, 행정동코드, 업종, 카드이용금액계, 카드이용건수계 (모두 캠퍼스 내부에서만 사용) |
| **처리 절차** | (1) 업종 텍스트에 F&B 키워드 부분일치 행만 필터<br>(2) 일자 → `YYYY-MM` 으로 통일<br>(3) 행정동×월 단위로 금액 sum, 건수 sum, 객단가(=금액/건수) 계산<br>(4) 데이터 기간을 자동 분할(6개월↑ 시 최근 3개월 vs 직전 3개월)하여 평균 비교<br>(5) `소비금액_증가율, 소비건수_증가율, 객단가_증가율` 각각에 z-score 표준화<br>(6) `소비성장점수 = 0.4·z(건수증가율) + 0.3·z(금액증가율) + 0.3·z(객단가증가율)` |
| **반출 컬럼** | `행정동코드, 소비금액_증가율, 소비건수_증가율, 객단가_증가율, 소비성장점수, 소비성장순위, 소비성장등급(A/B/C/D)` |
| **반출 안전성** | 금액/건수 원값과 단순합계는 컬럼에 존재하지 않음. 증가율(%)·z-score 가중점수·순위·등급만 포함. |

| **사용 컬럼** | start_dt(또는 arv_dt), start_emd, arv_emd, agegrd_nm, popl_cnt |
| **처리 절차** | (1) 연령 컬럼에 `20/20대/30/30대` 등 텍스트 매칭(없으면 숫자 20~39 fallback)으로 2030 행만 추출<br>(2) `start_emd ≠ arv_emd` 인 행을 외부유입으로 표시<br>(3) 도착 행정동 × 월 단위로 `popl_cnt sum` 두 종류(2030 전체 / 그 중 외부유입) 산출<br>(4) 최근/이전 평균 비교 → `2030유입_증가율 = (recent − prev) / prev`<br>(5) `외부유입비율 = 외부유입_recent / 2030유입_recent`<br>(6) 2030유입_recent 자체는 z-score 로만 변환(원값 미노출)<br>(7) `2030유입점수 = 0.5·z(증가율) + 0.3·z(외부유입비율) + 0.2·z(규모)` |
| **반출 컬럼** | `행정동코드, 2030유입_증가율, 외부유입비율, 2030유입점수, 2030유입순위, 2030유입등급` |
| **반출 안전성** | popl_cnt 원값·단순합계 컬럼 없음. 증가율과 비율, 표준화 점수만 포함. |

## 5. 반출 안전성 검증 절차

1. `outputs/export_safe/` 에 저장되는 모든 CSV/xlsx 는 **`save_export_safe()`** 또는 **`check_export_safe_columns()`** 함수를 거친다.
2. 두 함수는 코드 상단의 `BANNED_EXPORT_COLUMNS` 셋(약 50개)과 컬럼명이 정확 일치하는지 검사하고, 일치하면 `RuntimeError` 로 저장을 중단한다.
   - 금지 컬럼명 예: `카드이용금액계, 카드이용건수계, popl_cnt, 업소수, 정류장수, 역수, amount, count, total_amount, total_count, stop_count, station_count, ...`
3. PNG 그래프는 코드에서 명시적으로 `숫자 텍스트 라벨` 을 막대 위에 붙이지 않거나(①②③④⑤⑥⑦), 후보유형별 행정동 **개수**만 라벨로 붙이는 경우만 허용(⑧).
4. 모든 스크립트에서 `df.head() / print(df) / display(df)` 같은 원본 행 출력 호출이 사용되지 않는다.

## 6. 분석 한계 및 정성 주석

반출 보고서의 신뢰성을 위해 다음 한계를 명시한다.

1. **프랜차이즈 판정은 업소명 부분일치 휴리스틱** (약 70개 키워드)으로 수행되어, 새로운 브랜드/지역 브랜드는 로컬로 잘못 분류될 수 있음.
2. **2030 필터**는 데이터의 연령 컬럼 표기에 따라 텍스트 매칭 → 숫자 범위 매칭으로 fallback 한다. 매칭률이 낮으면 분석 결과의 대표성이 떨어질 수 있어 코드 로그(`2030 행 비율: X%`)를 함께 확인해야 한다.
3. **최근/이전 기간 분할**은 데이터 수집 기간에 따라 자동 조정된다(6개월 이상이면 최근 3개월 vs 직전 3개월). 본 보고서에 첨부되는 산출물의 실제 분할 결과는 실행 로그(`최근 기간: [...] / 이전 기간: [...]`)를 참조한다.
4. **B013 거래내역 미사용**: 본 보고서의 접근성 지표는 정류장/역 **메타 데이터(위치 정보)** 만으로 산출되었다. 즉 실제 이용량이 아니라 **이용 가능한 인프라 밀도** 를 표준화한 지표이다.
5. **행정동코드 ↔ 행정동명 매칭**: B021 만 행정동명 키이므로 `dong_lookup.csv` 가 없으면 다른 점수와 매칭이 비어 보일 수 있다. 매칭 누락 행은 후보 점수가 일부 컬럼 결측 상태로 들어가며, 결측은 평균값으로 보간된 뒤 정규화된다.

## 9. `DO_NOT_EXPORT_*` 파일의 의미와 캠퍼스 내부에서 얻어가야 할 인사이트

`outputs/internal_only/DO_NOT_EXPORT_*.csv` 는 **반출 금지** 파일이지만, 그 안에는 점수표(export_safe)만으로는 절대 보이지 않는 **절대 규모·표본 크기·시간 분포** 정보가 들어 있다.
캠퍼스를 떠나면 파일 자체는 가져갈 수 없으므로, **분석자가 캠퍼스 내부에 있는 동안 다음 항목들을 눈으로 확인하고 머리에 정리해서 나와야 한다.**

> 외부로 가지고 나갈 수 있는 것은 “그래서 어떤 인사이트를 얻었는가”를 정성 문장으로 정리한 PPT 발화/메모뿐이며, 절대 수치(금액·건수·인구수·업소수 등)는 PPT 본문에도 적지 않는다.

---

### 9-1. `DO_NOT_EXPORT_data_inventory.csv` — 데이터 인벤토리

**이 파일에 있는 정보**
- 파일별 크기(MB), 추정 행수, 컬럼 수, 인코딩, 구분자, 컬럼명 미리보기 30개, 날짜 컬럼 후보, 결측치 총합(샘플), 읽기 성공 여부.

**캠퍼스 내부에서 확인할 인사이트**
1. **데이터 누락 여부**: 4개 데이터셋(B079·B076·B021·B013) 중 raw 폴더에 못 들어온 파일이 있는지 확인. 누락이 있으면 캠퍼스 데이터 신청 단계를 다시 가야 함.
2. **데이터 기간 범위**: 날짜 컬럼 후보의 실제 분포를 보고 "최근 N개월 vs 직전 N개월" 분할이 우리가 의도한 기간으로 잡혔는지 확인. 03/04 점수가 부정확해 보이면 여기로 돌아와 기간부터 점검.
3. **인코딩/구분자 자동 탐지 결과**: 캠퍼스 데이터가 `cp949` 인지 `utf-8` 인지를 미리 파악해두면 다음 신청 때 같은 파일 형식 요청서 작성에 도움.
4. **B013 거래내역 파일이 raw 에 들어왔는지**: 들어왔다면 절대 사용하지 않았다는 사실을 보고서에 명시(이미 코드에서 자동 제외).

**나갈 때 가져갈 정성 인사이트 예시**
- "B079 는 X년 X월~X년 X월의 월별 데이터를 사용하였으며, 결측치는 미미한 수준이었다."
- "거래내역 파일은 신청에는 포함되어 있었으나 본 분석에서는 메타 파일만 활용하였다."

---

### 9-2. `DO_NOT_EXPORT_b079_monthly_internal.csv` — B079 행정동×월 소비 합계

**이 파일에 있는 정보**
- `행정동코드 × 월` 별 F&B 카드이용금액계 합계, 카드이용건수계 합계, 객단가(=금액/건수).

**캠퍼스 내부에서 확인할 인사이트**
1. **계절성/이벤트 효과 식별**: 특정 행정동에서 특정 월에 금액·건수가 튀는 패턴이 있는지(예: 연말, 봄축제 시즌). 점수표는 평균만 비교하므로 월 단위 변동성은 여기서만 볼 수 있다.
2. **최근/이전 기간 분할이 합리적이었는지 사후 검증**: 자동 분할된 최근 3개월에 비정상치(예: 코로나 같은 일회성 충격)가 끼지 않았는지 눈으로 확인.
3. **표본이 충분한 행정동인지**: 월 합계가 너무 작은 행정동은 증가율 계산이 불안정해진다. 점수가 극단적으로 높은 후보가 이 케이스에 해당하는지 점검.

**나갈 때 가져갈 정성 인사이트 예시**
- "TOP10 행정동은 모두 6개월 이상의 안정적인 월별 카드소비 데이터를 보유하고 있었다."
- "특정 월에 일회성 급증이 있는 행정동은 후보군에서 보수적으로 해석하였다."
